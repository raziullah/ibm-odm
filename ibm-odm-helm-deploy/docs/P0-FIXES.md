# P0 remediation notes (Dev)

- **Chart compatibility:** Publish downloads IBM ODM 26.0.3 and runs fail-closed default-key checks, `helm lint`, full template rendering and workload validation. No chart is bundled; the live chart must pass these gates. Unknown keys or non-rendering chart configurations stop publication.
- **Images:** Every rendered workload image (including init containers) must exist at the exact tag in the private ap-southeast-2 ECR account. ADO AWS role needs `ecr:DescribeImages` on each repository. Registry mapping is still driven by the vendor chart's actual values; validation intentionally rejects mismatches rather than silently rewriting them.
- **PostgreSQL TLS:** The rendered validator requires visible TLS JDBC configuration; this is a static gate, not a successful DB connection. Test a running ODM JDBC connection before declaring the deployment functional. Chart-specific SSL keys must match the downloaded chart.
- **ECR authentication:** Removed the assumption that a Kubernetes `ecr-pull-secret` already exists. For ROSA, ensure IBM amd64 worker-node IAM roles have `ecr:GetAuthorizationToken`, `ecr:BatchCheckLayerAvailability`, `ecr:BatchGetImage`, and `ecr:GetDownloadUrlForLayer` for the private repositories and that the cluster's ECR credential provider can use these credentials. Do not store 12-hour ECR tokens as permanent secrets. The bootstrap checks for amd64 IBM nodes but cannot inspect their IAM permissions; validate with a real image pull.
- **Limit:** Chart and ECR cannot be proven compatible offline without vendor chart download, ECR credentials, and live cluster testing. All failures stop the publish/bootstrap stages instead of allowing an unverified deployment.
